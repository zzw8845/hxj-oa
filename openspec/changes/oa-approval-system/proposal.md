## Why

海峡金 OA 审批系统目前仅有一个高保真 HTML 原型（`海峡金OA审批系统0827.html`），业务需求（多类型单据、多级审批、用印独立条线、角色权限、前置关联、补材料机制）已完整表达，但无后端、无持久化、无测试，无法真实运行。需要将原型沉淀为正式规范，并据此实现可部署的审批系统。

## What Changes

- 将原型中的业务规则固化为正式需求规范（单据、流程、角色、权限、审批操作）
- 实现后端服务：REST API + 数据库持久化（Spring Boot），**不开发前端**，前端由后续独立项目或第三方对接
- 数据库采用 **MySQL**
- 审批流采用**主流工作流引擎（Flowable）**，替代自研轻量引擎
- 实现认证与登录（原型中仅有账号字段，无真实认证）
- 实现审批全流程：提交、审批、驳回、补材料、加签、归档
- 实现用印申请独立审批条线
- 实现角色权限体系：人员只分配角色，权限由角色继承
- 提供完整的 OpenAPI 接口文档，供前端或其他系统对接
## Impact

- 代码：新增后端服务（Spring Boot + MySQL + Flowable）
- 数据：新增单据、流程配置、角色、人员、审批记录、归档台账等数据模型
- 依赖：Spring Boot、MySQL、Flowable 工作流引擎

## Capabilities

### New Capabilities
- `document-management`: 单据的创建、提交、查询、状态流转与生命周期管理（日常付款、业务付款、员工报销、用印申请四类），含单据分类规则、快捷单据目录、风险预警（高金额）
- `approval-flow`: 审批流程的配置与执行，包括 20 条业务单据的具体节点链、条件分支（金额阈值/涉及资金/按需）、抄送节点、流程透明度与前置资料穿透
- `approval-action`: 审批操作（通过、指定层级驳回、通过但补材料、加签）及审批记录留痕
- `role-permission`: 角色、权限点、数据范围与人员分配管理，权限由角色继承，含 19 个预置角色的具体配置
- `seal-management`: 用印申请独立审批条线（公章、合同章、法人章等）及用印凭证归档
- `archive-ledger`: 已通过单据的台账归档与多条件组合查询
- `user-auth`: 员工账号登录认证与身份识别
- `dashboard-analytics`: 首页统计（待办/已办结/已驳回）、工作看板（审批总量/节点效率/状态分布）、近7天流程趋势
