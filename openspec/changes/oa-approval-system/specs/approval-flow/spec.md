## Purpose

定义海峡金 OA 审批系统中审批流程的配置与执行机制，包括流程节点链、条件分支、流程透明度与前置资料穿透，确保每张单据按既定流程流转并全程留痕。

## ADDED Requirements

### Requirement: 流程配置管理
系统 SHALL 支持为每种业务单据配置审批流程。流程 SHALL 由有序的审批节点组成，节点 SHALL 支持从预设节点中选择或自定义输入。流程配置 SHALL 包含流程分类（日常/业务/用章）。系统管理员 SHALL 可新增、修改流程配置。审批/办理节点的审批人 SHALL 引用系统角色管理中真实存在的角色名（多角色用"/"分隔，任务对所有引用角色可见）；名称以"发起人"开头的回环节点 SHALL 动态指派给单据申请人本人。流程配置保存时 SHALL 校验引用的角色名有效，防止部署出无人可审的流程。

#### Scenario: 新增审批流程
- **WHEN** 系统管理员点击"新增流程"并填写流程名称、分类与审批节点
- **THEN** 系统保存该流程配置，并可用于对应业务单据的审批

#### Scenario: 修改审批流程
- **WHEN** 系统管理员修改某业务单据的审批节点顺序
- **THEN** 系统保存修改后的流程，后续新提交的单据按新流程流转

#### Scenario: 节点审批人引用真实角色
- **WHEN** 流程节点配置了审批人（如"会计主管&内控"）
- **THEN** 该角色的用户在"待我审批"中 SHALL 能看到停留于该节点的单据并发起审批

#### Scenario: 发起人回环节点动态指派
- **WHEN** 流程流转到名称以"发起人"开头的办理节点（如"发起人签收"）
- **THEN** 该任务 SHALL 指派给单据申请人本人，仅申请人可见可办理

#### Scenario: 部署前校验角色引用
- **WHEN** 系统管理员保存引用了不存在角色名的流程配置
- **THEN** 系统 SHALL 拒绝保存并提示无效的角色引用

### Requirement: 流程节点链执行
单据提交后 SHALL 按配置的节点顺序依次流转。每个节点 SHALL 有明确的审批人（或角色），当前节点审批通过后 SHALL 自动进入下一节点。提交时系统 SHALL 按申请事项匹配对应流程配置，并向提交人预览完整节点链。

#### Scenario: 按序流转
- **WHEN** 单据当前节点审批人通过审批
- **THEN** 系统将单据流转至下一节点，并更新当前节点与审批人

#### Scenario: 末节点通过
- **WHEN** 单据最后一个审批节点通过
- **THEN** 单据状态变为"已通过"，流程完结

#### Scenario: 提交时匹配流程并预览
- **WHEN** 用户在提交表单中选择业务项目（如"采购申请"）
- **THEN** 系统按申请事项匹配对应流程配置，并向提交人展示完整审批节点链

### Requirement: 条件分支
流程 SHALL 支持条件分支节点，根据单据属性（如金额、是否涉及资金）选择不同的后续路径。

#### Scenario: 金额触发分支
- **WHEN** 单据金额达到配置的阈值（如 ≥2 万元）
- **THEN** 系统自动将单据流转至更高层级审批节点

#### Scenario: 涉及资金触发分支
- **WHEN** 用印申请涉及资金事项
- **THEN** 系统自动将单据流转至会计主管&内控节点

### Requirement: 流程透明度与前置资料穿透
审批人 SHALL 可查看当前单据的全部前置节点信息、历史审批意见、操作时间与附件。每个节点 SHALL 标注"可查看前 N 个节点的全部信息与附件"。

#### Scenario: 查看前置节点信息
- **WHEN** 审批人打开单据详情中的"全流程"页签
- **THEN** 系统展示全部节点的状态、审批人、审批意见、时间与附件

#### Scenario: 查看前置附件
- **WHEN** 审批人打开单据详情中的"附件资料"页签
- **THEN** 系统展示全部节点上传的附件，含所属节点、上传人与时间

### Requirement: 流程配置展示
系统 SHALL 以可视化链条展示每种业务单据的审批流程（如"发起人 → 直属主管 → 会计 → 出纳"），供管理员查看与维护。

#### Scenario: 展示流程链条
- **WHEN** 系统管理员打开"流程管理"页面
- **THEN** 系统以节点链条形式展示全部业务单据的审批流程

### Requirement: 预置流程配置
系统 SHALL 预置以下 20 条业务单据的审批流程配置，每条流程 SHALL 包含明确的节点链与条件分支：

1. 闭店（入驻店销和代销）：发起人 → 条件分支 → 直属主管 → 商务专员/运营服务主管 → 执行总经理/公司领导 → 会计主管&内控 → 出纳 → 抄送相关负责人
2. 采购申请：发起人 → 直属主管 → 采购询价 → 行政主管（按需）→ 会计主管&内控 → 执行总经理（≥2万元）→ 采购办理 → 发起人签收
3. 低值易耗品（含办公物品）领用：发起人 → 直属主管 → 行政专员发放 → 发起人签收
4. 非标合同审批及用印：发起人 → 直属主管 → 会计主管&内控（涉及资金）→ 法务 → 法务主管 → 公司领导（涉及资金）→ 内控专员用印 → 发起人上传归档附件
5. 费用报销：发起人 → 直属主管 → 会计（按部门）→ 会计主管&内控 → 公司领导（大额）→ 出纳 → 抄送相关负责人
6. 费用预算：发起人 → 直属主管 → 会计主管&内控 → 发起人自选抄送
7. 应付款申请：发起人 → 直属主管 → 会计（按部门）→ 会计主管&内控 → 公司领导（大额）→ 出纳 → 抄送相关负责人
8. 公司发文申请：发起人 → 逐级主管 → 法务 → 内控主管 → 执行总经理 → 行政专员编号发文 → 发起人自选抄送
9. 固定资产报废报损：发起人 → 资产归属部门确认 → 财务经理 → 执行总经理 → 资产管理员办理 → 抄送管理人员
10. 固定资产调拨：发起人 → 调出部门确认 → 调入部门确认 → 调出/调入资产管理员办理 → 抄送财务及内控
11. 固定资产入库：发起人 → 直属主管 → 行政专员入库登记 → 抄送财务经理
12. 黄金业务开户：发起人 → 公司领导 → 抄送内控及内控主管 → 发起人办理 → 抄送总经办/法务/商务
13. 借款申请：发起人 → 直属主管 → 会计主管&内控 → 会计处理 → 出纳付款并上传回单 → 抄送财务及公司领导
14. 客户交易手续费调整：发起人 → 执行总经理 → 抄送财务/内控/法务/运营服务
15. 客户结算服务费：发起人 → 会计（按业务类型）→ 财务经理/内控主管/财务总监 → 会计主管&内控 → 出纳或商务对账 → 抄送相关负责人
16. 提货人新增或变更：发起人 → 交付主管 → 抄送内控主管及总经办
17. 通用审批申请：发起人 → 逐级主管 → 会计主管&内控（涉及资金）/执行总经理 → 抄送总经办
18. 业务招待申请：发起人 → 直属主管 → 会计主管&内控 → 执行总经理 → 抄送总经办
19. 银行账户管理调整：发起人 → 公司领导 → 出纳确认 → 内控主管 → 抄送财务/法务/商务
20. 用印及证照申请：发起人 → 直属主管 → 条件分支 → 运营服务主管/会计 → 会计主管&内控 → 财务经理 → 公司领导 → 内控专员用印或领取证照 → 发起人归还/商务归档 → 抄送内控主管

#### Scenario: 预置流程可查询
- **WHEN** 系统管理员打开"流程管理"页面
- **THEN** 系统展示上述 20 条预置流程的完整节点链

#### Scenario: 条件分支配置
- **WHEN** 流程配置包含条件分支节点（如"执行总经理（≥2万元）"、"会计主管&内控（涉及资金）"、"行政主管（按需）"）
- **THEN** 系统按单据金额、是否涉及资金等属性自动选择分支路径

### Requirement: 抄送节点
流程 SHALL 支持抄送节点，将单据抄送给相关角色或人员，并记录抄送记录。抄送节点 SHALL 不阻塞流程流转。流程配置为"发起人自选抄送"时，提交人 SHALL 可在提交时自选抄送对象。

#### Scenario: 抄送相关角色
- **WHEN** 单据流转至抄送节点（如"抄送相关负责人"、"抄送财务及内控"）
- **THEN** 系统向指定角色/人员生成抄送记录，流程继续流转不阻塞

#### Scenario: 查看抄送记录
- **WHEN** 用户打开单据详情
- **THEN** 系统展示该单据的全部抄送记录（抄送对象、时间）

#### Scenario: 发起人自选抄送
- **WHEN** 用户提交配置为"发起人自选抄送"流程的单据（如费用预算、公司发文申请）
- **THEN** 系统按提交人选择的人员/角色生成抄送记录
