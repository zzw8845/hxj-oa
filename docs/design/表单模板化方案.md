# 表单模板化设计方案（重开版·终态直上）

> 日期：2026-09-11 ｜ 状态：待开工确认
> 前提：单据/附件/审批记录/流程配置全部为 0（零存量数据），无兼容包袱
> 参照：钉钉审批模板控件 schema、芋道 BPM、form-create、Flowable 表单引擎废弃的行业结论

## 一、目标

表单从"代码"（固定 17 字段 DTO + 硬编码校验）重构为"元数据"（模板驱动）。
做完后：**新增/修改单据字段 = 界面配置，零发版**；表单与流程经"字段 key → 流程变量"结合。

## 二、关键决策（设计不变式）

| # | 决策 | 理由 |
|---|---|---|
| 1 | 系统属性不进表单：申请人/部门/状态/流程/单号/时间保留专列 | 引擎与列表的结构化根基 |
| 2 | 两个"提升字段"保留专列：`amount`（风险标记/列表排序/条件变量）、`title`（列表显示） | 引擎功能依赖；模板中为保留字段（可排序不可删除） |
| 3 | 其余字段全部模板化：用印五件套/合同号/发票摘要/事由明细等散列列删除，值进 JSON | 无存量数据，直接终态 |
| 4 | 单据冻结渲染快照：提交时存 `form_snapshot`（字段定义数组）+ `field_values`（值） | 模板后续变更不影响历史单据渲染（铁律①版本快照） |
| 5 | field_key 即未来条件变量名；保留键：amount/title/involvesFunds/requiresAdminReview/businessMode | 第 2 步"字段→条件变量提升"的结构预留 |
| 6 | 控件类型 v1 六种：TEXT/TEXTAREA/NUMBER/DATE/SELECT/BOOLEAN | 覆盖原型全部字段；照钉钉开放文档扩（图片/附件/明细表为远期） |

## 三、数据模型（V27 迁移）

```sql
CREATE TABLE form_template (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  business_type VARCHAR(50) NOT NULL UNIQUE,     -- 对应业务类型（与分类器/快捷名目对齐）
  name VARCHAR(100) NOT NULL,                    -- 如"通用审批单"
  version INT NOT NULL DEFAULT 1,                -- 字段变更 +1
  status VARCHAR(20) NOT NULL DEFAULT 'ENABLED'
);

CREATE TABLE form_field (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  template_id BIGINT NOT NULL,
  field_key VARCHAR(50) NOT NULL,                -- 稳定标识（保留键校验）
  label VARCHAR(100) NOT NULL,
  control_type VARCHAR(20) NOT NULL,             -- TEXT/TEXTAREA/NUMBER/DATE/SELECT/BOOLEAN
  required TINYINT NOT NULL DEFAULT 0,
  options TEXT NULL,                             -- SELECT 选项 JSON 数组
  reserved TINYINT NOT NULL DEFAULT 0,           -- 提升字段标记（不可删除）
  sort_order INT NOT NULL DEFAULT 0,
  enabled TINYINT NOT NULL DEFAULT 1,
  UNIQUE KEY uk_template_field (template_id, field_key)
);

-- oa_document 重构（零数据直接改）：
--   新增 form_template_id BIGINT / form_version INT / form_snapshot TEXT / field_values TEXT
--   保留 applicant/department/status/doc_code/amount/title/时间等系统与提升列
--   删除 invoice_summary/reason/contract_no/seal_project/seal_reason/seal_department/
--         seal_time/seal_file_name/seal_type 等散列列（值语义迁入模板字段）
```

**预置模板**：迁移种一份"通用模板"，字段=现有全部字段的等价定义
（含保留键 amount/title/involvesFunds/requiresAdminReview/businessMode + 事由明细/发票摘要/
合同号/用印五件套等），20 类单据直接可用。

## 四、后端改造（Spring Boot 3 / JPA / Flyway / Flowable 零改动）

| 模块 | 内容 |
|---|---|
| 实体/仓储 | FormTemplate、FormField；OaDocument 重构列 |
| FormTemplateManagementService | 模板 CRUD + 字段编辑（保留键不可删、field_key 保留字校验、SELECT options 校验、保存 version+1）；`GET /api/form-templates/enabled`（登录即可，渲染用）+ `/api/admin/form-templates` CRUD（配置权限） |
| 提交链路重写 | SubmitDocumentRequest v2 = `projectName / company / needPostMaterial / ccUserIds / fieldValues(Map)`；按模板驱动校验（必填/类型强转/SELECT 选项比对）；提升键提取：amount→列+风险标记，involvesFunds/requiresAdminReview/businessMode→流程变量；form_snapshot 冻结 |
| 详情合并 | 返回 `[{key,label,type,value,required}]` 成品数组，前端拿到即渲染 |
| 契约变化 | 原 DTO 的发票摘要/合同号/用印五件套等字段移除——由模板字段承接 |
| 测试 | 模板 CRUD/保留键保护/版本递增；提交校验四场景（缺必填/未知 key/类型强转/选项非法）；提升键提取；详情合并；集成测试 |

## 五·五、暗雷清单（2026-09-11 复审追加，四颗 + 控件扩充）

复审发现与 quick_document 同级的字符串解析暗雷，全部在本次重构中退役/转译：

| # | 位置 | 现状（猜） | 决策（显式） |
|---|---|---|---|
| 1 | OaCcNodeDelegate.ROLE_ALIASES | 抄送节点按节点名文案查硬编码别称表猜角色（6 条简称），原型自由文案大量落空 | FlowNodeConfig 增加结构化抄送目标（角色/部门/人员），别称表删除 |
| 2 | AttachmentRequirementService.requiredFor | projectName.contains("报销"/"供应商") 猜必附材料清单 | 前置材料要求进模板/流程配置（显式清单） |
| 3 | DocumentClassifier.BUSINESS_KEYWORDS + BusinessTypeEnum(3值,BX/FK/YY) | 关键词猜业务分类；新业务类型要发版 | 提交时显式选择模板（携带 templateId），分类器退役；业务类型配置化（模板携带 type_key+单号前缀） |
| 4 | flowConfigRepository.findByType(projectName) | 流程查找键=人写的名字（显示名=查找键），type 无唯一约束 | 提交 DTO 携带 templateId；FlowConfig.type 加唯一约束 |

**控件类型扩充（用户确认）**：v1 控件 = TEXT/TEXTAREA/NUMBER/DATE/SELECT/BOOLEAN +
**IMAGE/ATTACHMENT**（值=附件ID，oa_attachment 加 field_key 列关联）+
**TABLE 明细表**（options 定义列结构 [{key,label,type}]，值为行数组，校验递归到单元格）——共 9 种。

工作量修订：3-5 天 → 5-7 天（明细表控件 + 四颗暗雷退役与业务规则转译）。
测试重点：每颗暗雷一个钉子（抄送显式目标/模板驱动附件要求/类型显式提交/明细表递归校验）。

## 六、quick_document 退役（并入本次重构）

现状四怪：name 为手工跨表外键（须与 flow_config.type 逐字一致，错字静默吞条目）、
显示名与查找键混装、business_type 硬编码枚举、与 flow_config.category 重复分组。

处置：表退役。职责并入 form_template——
"哪些类型可提交"=enabled 模板（唯一事实源）、分组=business_type、显示名/排序=新增 display_name/sort_order 列。
快捷提交菜单由"enabled 模板 join 流程配置"派生，新增一种单据从两处配置变一处。

## 七、不做的事（边界）

- 拖拽画布设计器（字段清单编辑器足够，自用规模）
- 明细表格子表单/审批人绑定表单控件（钉钉深水区，远期）
- 扩展字段进列表搜索/排序（仅提升列可）
- 字段→条件变量的通用提升（第 2 步：出现"按非金额字段分流"需求时做，结构已预留）
